# Redesign Preservation

Read whenever changing an existing interface. Select preserve or overhaul explicitly.

## Define the mode

- **Preserve:** strengthen hierarchy, consistency, responsiveness, accessibility, and finish while
  retaining recognizable brand and interaction language.
- **Overhaul:** establish a substantially new visual language or composition. This changes the
  visual system, not every product contract.

If the request says only "make it better" and the two modes would produce materially different
work, ask which level of change is intended. Otherwise choose the least destructive mode that can
meet the stated goal and disclose it.

## Audit before editing

Record the current framework, package manager, components, tokens, design system, routes, content,
real assets, responsive rules, motion, data and API boundaries, forms, analytics, consent, legal
behavior, accessibility, SEO, tests, and performance constraints. Capture representative before
states when rendering is possible.

Separate three inventories:

- **Preserve:** working contracts and recognizable brand signals.
- **Improve:** hierarchy, consistency, content clarity, states, accessibility, responsiveness, or
  implementation debt within scope.
- **Change only with approval:** information architecture, behavior, data contracts, routes,
  analytics, legal meaning, content strategy, dependency model, and brand identity.

## Modernize in risk order

Prefer typography and hierarchy, spacing and rhythm, token consistency, states and focus, section
composition, then structural replacement. Escalate to larger change when the current structure
cannot support mobile use, accessibility, comprehension, or the stated product goal.

Do not silently rename routes, anchors, events, form fields, labels, or public content; replace
authentic assets; remove supported themes; or alter server/client, caching, SEO, or consent behavior.

## Compare before and after

Replay route coverage, navigation, content, data, forms, analytics, accessibility, SEO, responsive
behavior, supported themes, performance, and relevant tests. Record intended differences. A more
attractive screen that loses task continuity or product behavior is a regression.
