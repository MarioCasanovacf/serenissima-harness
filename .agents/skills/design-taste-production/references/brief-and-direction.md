# Brief and Direction

Use this reference on every task. Convert incomplete taste language into an explicit design
decision without inventing business facts.

## Build the brief

Capture only what affects the work:

- Surface and operating mode.
- Audience, user job, business goal, and primary success signal.
- Existing brand, content, product, technical, legal, accessibility, and delivery constraints.
- Required content, controls, routes, data, and states.
- Supplied visual references and the qualities to borrow or avoid.
- Unknowns that could change structure, product behavior, or the primary direction.

Ask a question only when an unknown would materially fork the result. Otherwise state a reversible
assumption and continue. Never substitute invented copy, metrics, testimonials, inventory, people,
or product behavior for missing information.

## Inspect the target

For an existing project, inspect representative components, layout shells, tokens, styles, content,
assets, package manifests, lockfiles, build scripts, route definitions, API or schema boundaries,
analytics and SEO integration, tests, and accessibility patterns. Find the native way the project
already expresses spacing, type, color, interaction, and responsive behavior.

For greenfield work, honor the user's requested environment. If none is named, choose the smallest
implementation that meets the delivery context; do not select a framework to demonstrate taste.

## Declare one direction

Write a compact design read containing:

1. Primary mode and secondary mode, if any.
2. Audience and job to be done.
3. Visual language in concrete terms such as geometry, contrast, type character, material, image
   role, and rhythm.
4. Density posture: airy, balanced, compact, or data-dense.
5. Motion posture: none, feedback-only, structural, or narrative.
6. Foundation: existing system, named official system already in use, or custom project-native
   primitives.

Optional numeric dials can make tradeoffs visible: DESIGN_VARIANCE, MOTION_INTENSITY, and
VISUAL_DENSITY from 1 to 10. Derive them from the brief rather than treating any values as defaults.

## Direction test

A usable direction explains why this interface should look and behave this way for this audience.
Reject directions that depend only on a fashionable label, force every section into the same
template, erase a functioning brand, or require unapproved technical migration.
