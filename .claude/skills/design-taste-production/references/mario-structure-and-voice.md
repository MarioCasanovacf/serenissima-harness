# Mario structure and voice

Express Mario's system structurally, not by pasting tokens onto a generic composition. Aim for a
sober, serene, objective, clear, scientific, anti-performative register: Mitteleuropean editorial
modernism with fine-paper-and-ink materiality rather than app-like polish.

- Default to a light warm-paper canvas only while `personal:mario` is active. Use wide margins,
  single-column reading measures, numbered sections, hairline rules, square corners, and
  essentially no shadow. Let charts and diagrams serve as evidence.
- When assets permit, use GFS Didot for display, EB Garamond for prose, IBM Plex Sans for UI and
  charts, and IBM Plex Mono for data and notes. Preserve an existing type system when replacement
  is not authorized; document substitutions instead of silently fetching fonts.
- Write precise claims in sentence case. Use first person singular for personal statements and an
  impersonal register for case-study exposition. Translate patiently without simplifying away the
  method. Use no exclamation marks, emoji, startup language, promotional superlatives, or brand-we.
- Reject gradient, glow, glass, blur, large radius, ornamental shadow, automatic dark mode,
  glossy stock imagery, spring, bounce, scale, and generic high-tech or startup presets. Keep
  motion quiet, optional, and functional.

The result should feel composed as a monograph, annual report, or analytical plate. Restraint is
not emptiness: establish tension through type scale, measure, rules, evidence, and exact spacing.
